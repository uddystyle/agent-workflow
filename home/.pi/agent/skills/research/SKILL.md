# 調べて、残す

**会話に残さない。** 調べた結果が会話の中にしか無ければ、次のセッションには届かない。
この skill の成果物は**ファイル1枚**である。

🔴 **一次情報に当たる。** 要約・二次記事・以前の記憶は根拠にならない（`DECISIONS.md` D-2 / D-20）。

## 1. 正本がどこにあるかを先に探す

書き始める前に、**その主題の正本**を探す。とくに**道具に同梱された文書**（D-20）。

```sh
ls ~/.agents/skills/          # いま配られている正本
<道具> --help                 # 道具が自分で配る形
```

⚠️ **正本があるのに一から書くと、劣化した写しができる。** 実際に60行書いて全撤去になった（D-20）。

**完了条件**: 主題の正本が「在る（場所を言える）」か「無い（探した範囲を言える）」かを言える。

## 2. 読む仕事を分けるかを決める

読む量が多いときは `survey` へ委譲する。

```
subagent: agent=survey, task=<何を調べ、何を返してほしいか>
```

🔴 **委譲先はそれ以上委譲しない。** `survey` の定義は `tools: read, grep, find, ls` だけを持ち、
**委譲する道具を持っていない**——文で禁じるのではなく、道具で塞いである（`doctor` が毎回検査する）。

⚠️ **止まったからといって2本目を立てない。** 止めて、自分で続きをやる。

**完了条件**: 委譲したなら、返ってきたものが**ファイルを見ていない相手にも読める**形になっている。

## 3. 主張ごとに出典を書く

書くのは**1ファイル**。主張1つに、それを持っている場所を1つ。

- 逐語で引くか、コマンドで引き直せる形にする
- ⚠️ **要約器の出力を引用に使わない。** 逐語で取り直す
- 🔴 **確かめていないものは「確かめていない」と書く。** 書かないのではなく、書く

**完了条件**: 各主張について、出典か再現コマンドが付いている。付かないものには「未確認」が付いている。

## 4. 置き場所を決める

**調べた対象の repo に置く。** その repo が notes をどこに置いているかに合わせ、
合わせ先が無ければ置いた場所を言う。

🔴 **他プロジェクトの事実を、この repo に持ち込まない**（D-10）。
道具や API の一般的な挙動はここでもよいが、**そのプロジェクトのドメイン事実は、そのプロジェクトへ**。

**完了条件**: ファイルの場所を1つ言え、そこがなぜその場所かを言える。
