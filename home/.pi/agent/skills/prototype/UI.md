# 見た目を比べる試作

**複数の案を、同じ場所で切り替えて見比べられるようにする。**

## 1. 形を選ぶ。既存の画面を優先する

| | いつ | 後始末 |
|---|---|---|
| **A: 既存の画面に案を足す**（優先） | その画面を直したい | 勝った案を本体へ畳み、負けた案と切替器を落とす |
| **B: 使い捨ての画面を作る**（最後の手段） | 置き場がまだ無い | 勝った案を本物の経路へ昇格し、使い捨ての画面を落とす |

🔴 **B を選ぶ前に、A で置けないかを考える。** 新しい経路は、消し忘れると本番に残る。
B にするなら、**名前に「prototype」を入れる**。

**完了条件**: A か B かを言え、B なら A では置けない理由を言える。

## 2. 案を3つ作る

**既定は3案。** ⚠️ **5を超えない**——それ以上は「大きく違う案」ではなく、ただの雑音になる。

🔴 **大きく違えること。** 色や余白の差では、見比べる意味がない。**配置と情報の出し方**を変える。

**完了条件**: 3案それぞれについて、**何を変えたか**を1行で言える。

## 3. 切り替えを1箇所にまとめる

- URL のクエリ（`?variant=`）で選ぶ
- **画面下に浮かぶバー**を置き、左右の矢印で送る。**キーボードの矢印にも反応させる**
- 切替の処理は**共有の部品1つ**に置く。案ごとに書かない

⚠️ **切り替えたら、いまどれを見ているかを画面に出す。** 見比べているうちに分からなくなる。

**完了条件**: URL を渡せば、相手が同じ案を開ける。

## 4. 渡して、待たない

場所と、見てほしい点を伝える。⚠️ **こちらでターンを終える。**

**完了条件**: URL を伝え、何を選んでほしいかを1文で言った。

## 5. 答えと試作を捕まえる

- **答え** —— どれを選び、なぜか。判断の置き場へ
- **試作** —— 🔴 **全案を捨てブランチへ**。main には勝った案だけを残す

⚠️ **負けた案も残す価値がある。** 「なぜそれを選ばなかったか」は、後から必ず聞かれる。

**完了条件**: main に勝った案だけがあり、全案の在処を言える。

## やってはいけない形

- ⚠️ **案が似ている** —— 見比べても差が出ず、時間だけ使う
- ⚠️ **切替器が案ごとにある** —— 直すときに全部直すことになる
- 🔴 **使い捨ての経路を消し忘れる** —— 名前に「prototype」が入っていないと、誰も気づかない
