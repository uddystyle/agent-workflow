# 検査を先に書く

**検査は仕様として読めるものにする。** 「有効なカートで購入できる」は、**何ができるか**を言っている。
実装を全部書き換えても、この検査は生き残る。

## 1. どこで観るかを先に合意する

**seam** ＝ 中に手を入れずに振る舞いを観られる、**公開された境目**。検査は seam に置く。

🔴 **合意していない seam では書かない。** 書く前に、どの seam で観るかを挙げて**人に確かめる**。
全部は試験できないので、**先に決めることが、労力を重要な経路へ落とす唯一の方法**である。

⚠️ **seam が1つしか無いこともある。** コマンドライン道具なら「引数・終了コード・出力」しかない。
そのときは合意に時間をかけない——**選択肢が無いことを言って進む**。

**完了条件**: 検査を置く seam を挙げ、人が認めた。

## 2. 縦に1枚ずつ切る

🔴 **検査を全部書いてから実装しない。** まとめて書いた検査は、**想像した振る舞い**を試験する——
物の**形**を確かめているだけで、実際の変化に鈍くなる。

**1検査 → 1実装 → 繰り返す。** 各検査は**曳光弾**であり、**前の1周で分かったことに応じて次を決める**。

**完了条件**: 各周回について、その検査が**前の周回の結果を受けている**と言える。

## 3. 落ちる検査を先に見る

**Red before green.** 落ちる検査を書き、**通すだけの最小の実装**をする。先回りしない。

🔴 **書いた検査は、わざと緩めて落ちるところまで見る**（`AGENTS.md`）。
落ちなければ、その検査は**構造上必ず通る**——コードと食い違えないものは、何も守っていない。

**完了条件**: 各検査について、**緩めたら落ちた**と言える。

## 4. やってはいけない3つの形

| 形 | 中身 | **見分け方** |
|---|---|---|
| **実装に癒着** | 内部の協力者を差し替える、private を試験する、裏口から観る（インターフェースでなく DB を直接見る） | 🔴 **振る舞いは変えていないのに、整理しただけで壊れる** |
| **同語反復** | 期待値を、コードと同じ手順で計算する | 🔴 **必ず通る。** 期待値は**独立した出所**から取る——既知の値、手で解いた例、仕様 |
| **横切り** | 検査を全部書いてから、実装を全部書く | §2 のとおり |

**完了条件**: 書いた検査それぞれについて、3つのどれにも当たらないと言える。

## 5. 整理はループの外に置く

🔴 **refactor を red → green の中でやらない。** それはレビュー段の仕事である（`two-axis-review`）。

⚠️ 緑になった直後に整理したくなるが、**そこで手を入れると、何が通したのか分からなくなる**。
