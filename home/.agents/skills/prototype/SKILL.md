# 捨てる前提で作る

**試作とは、問いに答える使い捨てのコードである。** 何を作るかは**問いが決める**。

🔴 **問いを1つに絞ってから始める。** 「だいたい確かめたい」で作ると、何が分かったのかを言えない。

## 1. 形を選ぶ

| 問い | 開くもの |
|------|----------|
| **状態の動きは、これで合っているか** | [LOGIC.md](LOGIC.md) |
| **見た目はどれがよいか** | [UI.md](UI.md) |
| **測り方は、これで測れているか** | 下の「測る試作」 |

⚠️ **選び間違えると、試作まるごとが無駄になる。** 成果物の形がまったく違う。

人に聞けないときは周りのコードで決め（画面なら UI、それ以外なら LOGIC）、**仮定を先頭に書く**。

**完了条件**: 答えたい問いを1文で言え、選んだ形の理由を言える。

## 2. 共通の規則

1. **初日から捨てる前提。名前でそう分かるようにする。** 使う場所の近くに置く
2. **走らせるのが自明。** 1コマンド、あるいはダブルクリック
3. **保存しない。** 状態はメモリに置く。DB が問いの一部なら、**捨てると分かる名前**を付ける
4. **磨かない。** 検査も、抽象化も、動く以上のエラー処理も要らない
5. 🔴 **状態を見せる。** 操作のたびに、関係する状態を**全部**出す。見えないものは確かめられない

**完了条件**: 5つとも満たしている。満たさないものは、なぜ外したかを言える。

## 3. 測る試作

**この repo 群でいちばん多い形である。** 「いま何文字載っているか」「どの経路で入ったか」を
数えるための、短い使い捨て。

- 🔴 **値を出さない。** 数と場所と名前だけ出す（`AGENTS.md` の固定文）
- 判定を持つなら、**既にある表を読む**。二組目を作らない
- ⚠️ **空振りでないことを確かめる。** わざと当たる入力を1つ通して、**検出されること**を見る

**完了条件**: 同じ数字がもう一度出せる。出せないなら、それは測定ではなく印象である。

## 4. 答えと道具を捕まえる

🔴 **答えだけ残して、測り方を捨てない。** 次に同じことを測りたくなったとき、また書くことになる。

- **答え** —— 何が分かったか、どの問いが決着したか。判断の置き場へ
- **試作そのもの** —— 捨てブランチに commit するか、消すかの二択（`.gitignore` の方針）
- ⚠️ **どちらでもよいが、決めずに一時領域へ置いたままにしない**——セッションと一緒に消える

**完了条件**: 答えの置き場を言え、試作を**残したか捨てたか**を言える。

## やってはいけない形

- ⚠️ **問いが2つある試作** —— どちらにも答えられない
- ⚠️ **本番に混ざる試作** —— 名前で見分けが付かないものは、いつか誰かが本番だと思う
- 🔴 **磨いてしまった試作** —— 捨てにくくなり、捨てられないものは本番になる
