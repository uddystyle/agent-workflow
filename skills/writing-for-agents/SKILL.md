# エージェント向けに書く

相手にするのは**エージェントの context に載る文書**である——`skills/*/SKILL.md`、`AGENTS.md`、
`DECISIONS.md`、`NEXT.md`、スクリプトの中のコメント。

**この文書の唯一の規律**: 書く1行ごとに、**その行が既定の振る舞いを変えるか**を言えること。
変えない行は載せない。読んで気持ちがよいことは、根拠にならない。

## 1. どちらの負荷を払うかを決める

書き足すものは、必ずどちらかを払う。

| 負荷 | 誰が払うか | 何が乗るか |
| ---- | ---------- | ---------- |
| **context** | エージェント（毎ターン） | `AGENTS.md` の行、スキルの description。発火しなくても乗る |
| **認知** | 人 | 「どの文書がいつ要るか」を覚えていること |

指し先（description、`AGENTS.md` の1行）の**後ろ**に置いた材料は、指し先1行分だけで済む。
指し先すら無い材料は、人の記憶だけが頼りになる。

🔴 **認知負荷を0にしようとしない。** それは人が判断する余地そのものである。
判断が要らないところから削る。

**完了条件**: いま足そうとしている材料について、毎ターン載せるのか、指し先の後ろに置くのかを言える。

## 2. 指し先を書く

**発火を決めるのは指し先の言葉であって、指した先の中身ではない。**
中身がどれだけ良くても、言葉が鈍ければ届かない。

指し先が担うのは2つ。**何であるか**と、**どの分岐で来るか**。

- 発火させたい語を**先頭に置く**
- 分岐は**互いに別物のものだけ**並べる。言い換えで増やさない
- 本文が名乗っている素性を、指し先で繰り返さない

⚠️ **中身を本体に写して解決しない。** まず言葉を鋭くする。鋭くしても届かないと分かってから、写す。

**完了条件**: description の分岐が互いに別物で、同義語による重複が無い。

## 3. 階層に置く

材料は3段のどこかに置く。上ほど、すぐ要る。

1. **手順** —— 順にやること
2. **その場の参照** —— 必要になったとき読む規則・定義。平らに並ぶのは正常である
3. **外へ出した参照** —— 別ファイルに出し、指し先から辿る

**判定は分岐で決まる。すべての分岐が読むものは中に置く。一部の分岐しか読まないものは外に出す。**

⚠️ 出しすぎると、要るものが隠れる。出さなすぎると、頭が膨らんで手順が埋もれる。

1つの概念の**定義・規則・落とし穴は同じ見出しの下に置く**。散らすと、片方だけ読まれる。

**完了条件**: 各かたまりが3段のどれかに置かれ、外に出したものには指し先がある。

## 4. 完了条件を付ける

節の終わりには、**終わったと分かる条件**を置く。効くかどうかは2つで決まる。

- **判定できるか**——「理解した」は判定できない。「どのファイルの何行目から取ったかを言える」は判定できる
- **どれだけ要求するか**——「一覧を作る」より「**変更したもの全部について**説明できる」のほうが手が動く

⚠️ **早すぎる完了**が起きる。先の手順が見えていると、目の前の節を切り上げたくなる。
**まず条件を鋭くする**。鋭くしようがなく、かつ実際に急ぐのを見たときだけ、手順を分けて後を隠す。

🔴 **隠れるのは context の境目を越えたときだけである。** 引き継ぎや委譲は隠れる。
同じ context の中で呼んでも、後の手順は見えたままで、何も隠れていない。

**完了条件**: 各節の完了条件が、判定でき、かつ手を抜けない要求量を持つ。

## 5. 肯定で書く

**禁止で操らない。** 禁止した振る舞いを書いた時点で、それが context に載る。
載れば選ばれやすくなる——禁止は弱く、載った概念は強い。

目標の振る舞いを書く。禁止は、**肯定で言い換えられない硬い柵**のときだけ置く。
そのときも、肯定の目標を隣に併記する。

**先導語**を使う。model が既に持っている語を、**token として繰り返す**（文として説明しない）。
繰り返すうちに定義が溜まり、少ない語で広い振る舞いを固定できる。
造語も効くが、priors を借りられないぶん、定義の token を自分で払う。**まず既存の語を探す。**

**完了条件**: 禁止で書いた行それぞれについて、肯定で言い換えを試した跡がある。

## 6. 剪定する

- **同じ意味は1箇所に置く。** ここは `DECISIONS.md` D-2 が正本である——引けるものは書かず、引くコマンドを書く
- **環境が正本のものを書かない。** 書けばそれは複製であり、環境より先に腐る。書くのは**引けないもの**だけ——決めた理由、書かれていない約束、設定が白状しない罠
- **既定で守ることを書かない。** 判定は「この文を消したら振る舞いが変わるか」である。
  🔴 **走らせて決める。議論で決めない**——意見が割れたときに割れているのは既定の見立てであって、文ではない
- 落ちた文は**行ごと落とす**。語を削って残さない

⚠️ 足すのは安全に見え、消すのは危険に見える。放っておくと**古い層が沈んで積もる**。

**完了条件**: 文ごとに「消したら変わるか」を通し、落としたものを言える。

## 7. 分けるかを決める

分けると、context 負荷は下がるが**認知負荷が上がる**（§1）。払う理由が要る。

- **順序で分ける**——先の手順が見えていて急ぐとき（§4）
- **呼び出しで分ける**——人が明示的に呼ぶ入口と、model が自分で呼ぶ本体を分けるとき

**完了条件**: 分けたなら、どちらの負荷を減らすために分けたかを言える。
