# 引き継ぎを書く

引き継ぐのは**会話ではなく、次の一手**である。

**この文書の唯一の規律**: 書く1行ごとに、**それが無いと次が困るかを言えること**。
困らない行は書かない。経緯の再現も、やったことの一覧も、それだけでは根拠にならない。

⚠️ **`disable-model-invocation: true` を付けてある。** 引き継ぐ瞬間は人が決める。
エージェントが自分の判断で会話を畳み始めるものではない。

## 1. 何に渡すかを聞く

引き継ぎ先が何をするかで、残すものが変わる。**分からないまま書き始めない。**

聞いていなければ、一言で聞く——「次のセッションは何に使いますか」。

**完了条件**: 次にやることが1文で言える。

## 2. 成果物は指すだけにする

既にあるものを**書き写さない**。パスか URL で指す。

```sh
git log --oneline -10          # どのコミットまで進んだか
git status --short             # 手元に何が残っているか
git log --oneline origin/main..main   # 送っていないもの
```

設計・計画・判断・issue・差分は、**在処だけ**を書く。
🔴 **写した時点で、片方が古くなる場所が1つ増える。**

**完了条件**: 引き継ぎの中に、他のファイルから写した段落が1つも無い。

## 3. 引けないものだけを書く

環境を見れば分かることは書かない。**見ても分からないもの**を書く。

| 書く | 書かない |
|------|----------|
| なぜその方針にしたか | 何をしたかの一覧 |
| 試して駄目だった案と、駄目だった理由 | コマンドの出力 |
| 次に触ると壊れるところ | ファイルの中身 |
| 判断待ちになっていること | git log で読めること |
| ⚠️ **確かめずに書いた箇所** | 確かめた事実そのもの |

**完了条件**: 各行について「これは環境から引けるか」と聞いて、すべて「引けない」と答えられる。

## 4. 秘密を落とす

🔴 **鍵・トークン・個人を特定する情報・顧客の内容を、そのまま置かない。**

引き継ぎは会話の外へ出る。⚠️ **一度書けば、消しても読まれた後である。**

出所を指す形にする——「`.env` の `STRIPE_SECRET_KEY`」であって、値ではない。

**完了条件**: 値そのものが1つも入っていない。名前だけになっている。

## 5. 次に呼ぶスキルを挙げる

次のセッションが最初に読むべきスキルを名前で挙げる。
**呼ぶ順序に意味があるなら、順序も書く。**

**完了条件**: 挙げたスキルが実在する（`ls ~/.agents/skills/`）。

## 6. 置く

repo の中に置かない。**OS の一時領域に置く**。

```sh
mktemp -t handoff
```

⚠️ **プロジェクトには何も置かない**（`DECISIONS.md` D-3）。引き継ぎは道具であって、
成果物ではない。repo に入れると、次のセッションが終わっても残り続ける。

書いたらパスを人に伝える。**渡すのは人であって、ファイルではない。**

**完了条件**: パスを伝えた。repo の作業ツリーが汚れていない（`git status --short` が空）。

## 7. 読めるか確かめる

書いた1枚だけを読んで、次の3つに答えられるか自分で試す。

- **次に何をするか**
- **触ると壊れるものは何か**
- **判断待ちになっているものは何か**

**完了条件**: 3つとも答えられる。答えられないものがあれば §3 に戻って材料を足す。
⚠️ **答えられないまま渡さない。** 渡した後は聞けない。
