# 2つの観点で見る

**1人で全部見ない。** 観点ごとにサブエージェントを分け、**context を分ける**。

これは人格の分離ではなく context の分離である（`DECISIONS.md` D-1）。
同じ context で規約とスペックを同時に見ると、**片方が片方を隠す**——
規約違反を直しているうちに「そもそも頼まれていない変更」を見落とす。

## 1. 起点を決める

比較の起点を1つに固定する。コミット・ブランチ・タグ・merge-base のいずれか。

```sh
git diff --stat <起点>...HEAD
```

⚠️ **差分が空なら、そこで止める。** 起点が違っている。

**完了条件**: 起点が解決でき、差分が空でない。

## 2. 材料を集める

観点ごとに、判断の拠り所になるものを探す。**推測で補わない。**

```sh
cat AGENTS.md                                    # 規約の正本
git log <起点>..HEAD                             # 何を意図した変更か
git log <起点>..HEAD --format=%B | grep -oE '#[0-9]+|[A-Z]+-[0-9]+'   # 票や issue の番号
ls docs/*/specs 2>/dev/null                      # 設計文書があるか
```

見つからなければ「**無い**」と記録する。⚠️ **無いものを想像して補わない。**

🔴 **拠り所を狭く渡さない。** 文書だけを渡すと、**会話で頼まれた変更が「余分」に見える**。
実際にそうなった——文書に無い変更が3件、頼まれていないものとして挙がったが、
そのうち2件は**会話で直接頼まれたもの**だった。

**スペックの観点には、この範囲で頼まれたことを全部渡す。**

- 文書に書かれた依頼（設計・票・issue・判断の記録）
- **会話で頼まれたこと**——文書に残っていないなら、渡すときに書き起こす
- **検査が落ちて直したもの**——依頼ではないが、余分でもない

⚠️ **渡さなかったものがあれば、そう伝える。** 「これで全部」と言えないなら、
受け取った側は「余分」と「範囲外」を区別できない。

**完了条件**: 2つの観点それぞれについて、拠り所が実在するか「無い」かを言える。
スペックの観点に渡した拠り所が、**この範囲で頼まれたことを網羅している**と言える。

## 3. 分けて出す

**2つのサブエージェントに、それぞれ差分と拠り所だけを渡す。**

🔴 **観点の中身をここに書かない。** 正本は次の2枚である。**渡す前に読む。**

```
home/.pi/agent/agents/standards.md    規約の観点
home/.pi/agent/agents/spec.md         スペックの観点
```

⚠️ **写して渡さない。読ませる。** 写した瞬間、同じ規律が2箇所に住む（D-2）。
道具が違っても観点は同じものであり、**片方だけ直る状態を作らない**。

🔴 **始める前に `REVIEW_SUBAGENT` を見る。** ここで道が2つに分かれる。

| 変数 | 自分は誰か | やること |
| ---- | ---------- | -------- |
| **立っている** | 委譲先である | 変数が名指す観点**だけ**を、自分の context と道具で見切る |
| **立っていない** | 分ける側である | 観点ごとに1つ起こし、変数を渡す |

```sh
herdr pane split --cwd <対象の repo> --env REVIEW_SUBAGENT=standards
herdr pane split --cwd <対象の repo> --env REVIEW_SUBAGENT=spec
```

⚠️ **「さらに下へ委譲するな」と書くだけでは弱い。** 禁じたい振る舞いを書けば、その語が相手の
context に載る。**状態で分岐させる**ほうが確実である。文で伝えるのは、状態を渡せないときだけにする。

⚠️ **同じ process の中で呼ぶ委譲には効かない。** 環境変数は親から継がれるので、
呼ばれた側は自分が委譲先かを見分けられない。そのときは文で伝えるしかなく、
**この守りは無いものとして数える**（D-1）。

**完了条件**: 2つが独立に走り、互いの結果を見ていない。委譲先では変数が立っており、
自分が見る観点をそこから読んでいる。

## 4. 並べて報告する

観点ごとに見出しを分けて出す。**混ぜない。順位を跨いで付け直さない。**

各観点について書くこと。

- **規約違反**（決まりに反している。直す）と**判断**（気になるが決まりは無い）を**分ける**
- 指摘ごとに、**どのファイルのどこか**と、**なぜそう言えるか**
- 🔴 **確かめたかどうかを書く。** 走らせて確かめたのか、読んだだけなのか

⚠️ **どちらの観点が重いかを決めない。** 決めるのは人である。

**完了条件**: 2つの見出しが並び、各指摘に根拠と「確かめたか」が付いている。

## 5. 見落としを自分で疑う

出し終えたら、**指摘が0件の観点**について1度だけ問い直す。

- 材料が無かったのか（§2 で「無い」と記録したか）
- 見たが無かったのか

**この2つは違う。** 前者は「見られなかった」であって「問題が無い」ではない。

**完了条件**: 0件の観点について、どちらだったかを書いている。
