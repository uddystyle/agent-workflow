# AGENTS.md を生成する

`AGENTS.md` はエージェントの context に毎回載る。**短く、高信号で、いつの事実かが分かる**状態に保つ。

**この文書の唯一の規律**: 書く1行ごとに、**repo のどこを見て書いたかを言えること**。
言えない行は書かない。推測も、以前の記憶も、既存の `AGENTS.md` の記述も、根拠にならない。

## 1. 環境を読む

コマンドで引く。読んだ場所を手元に控える。

```sh
git rev-parse HEAD                    # 刻む対象コミット
ls -a                                 # 何がある repo か
cat package.json 2>/dev/null          # scripts が test / lint / build の正本
cat Makefile justfile 2>/dev/null     # 同上
cat .gitignore                        # 生成物と秘密の在処
git ls-files | sed 's|/[^/]*$||' | sort -u | head -40   # 実際の階層
```

言語やフレームワークは、マニフェストの実在で決める（`package.json` / `Cargo.toml` / `go.mod` / `Package.swift` / `pyproject.toml`）。

取れなかったものは「未定義」と書く。⚠️ **そこで終わらせない**——検査が無い repo では、
**変更したとき人が何を確かめるか**を書く。エージェントは「テストが無い」を「確かめなくてよい」と読む。

🔴 **確かめ方に repo の外への副作用があるなら、封じ込め方まで書く。**
書かなければ、確かめた瞬間に環境が壊れる。

**完了条件**: runtime・test・lint・build の各コマンドについて、**どのファイルの何行目から取ったかを言える**。「未定義」と書いたものには、代わりの確かめ方が付いている。

## 2. 境界を見つける

エージェントが壊しやすいものを特定する。

```sh
git check-ignore -v <疑わしいパス>    # 生成物かどうかは gitignore が答える
git ls-files | grep -iE 'migration|schema|lock'
```

**生成物**（`.gitignore` に載っている、またはツールが吐くと明記されているもの）、
**手で書き換えると壊れるもの**（migration、lock ファイル）を挙げる。

🔴 **repo の外へ書くものがあれば、その書き込み先を開いて中を見る。**

```sh
git ls-files | xargs grep -lE '\$HOME|~/|/etc/|launchctl|defaults write' 2>/dev/null
ls -l <書き込み先>                    # 何が同居しているか
```

書き込み先は、この repo だけのものとは限らない。**別の管理系が同居していれば、
名前の衝突と上書きがそのまま境界になる。**

⚠️ **これは repo の中をいくら見ても出てこない。** 書き込み先を開くまで、
「同居していない」と「見ていない」が区別できない。

**完了条件**: 挙げた境界すべてについて、**なぜ境界なのかを1行で言える**。
repo の外へ書くものについては、**書き込み先を実際に見た上で、同居している管理系を挙げた**——
無いなら「見た結果、無い」と言える。

## 3. 依存を見つける

この repo が外と何を話すかを、**設定と環境変数名から**取る。

```sh
cat .env.example 2>/dev/null          # 名前だけ。値は読まない
```

⚠️ **値は読まない。** 名前だけを使う。

**完了条件**: 挙げた依存が、設定ファイルか環境変数名に実在する。

## 4. 書く

[TEMPLATE.md](TEMPLATE.md) の形で `AGENTS.md` を書く。冒頭に生成日時と対象コミットを刻む。

**5KB を目安にする。** 超えたら、節ではなく**行を削る**——1コマンドで引ける事実が紛れ込んでいる。

**完了条件**: 全行について §1 の規律を満たす。日時とコミットが入っている。
**印の横に、その印を疑う条件が入っている**——対象パスが埋まっていて、そのまま実行できる。

## 5. 落としたものを見せる

既存の `AGENTS.md` があった場合、**何を落としたかを一覧で出す**。消したまま黙らない。

```sh
git diff --stat AGENTS.md
```

落とした内容を3つに分ける。

| 分類                       | 扱い                                       |
| -------------------------- | ------------------------------------------ |
| 環境から引ける事実         | 落としてよい。腐る側だった                 |
| 引けない事実（判断・罠）   | 🔴 **別の場所に移す**。消してはいけない    |
| 実態と食い違っていた記述   | 落としてよい。ただし食い違いを報告する     |

**完了条件**: 落とした行がすべて3分類のどれかに入り、2番目のものに移し先がある。

## 6. 使えるか確かめる

生成した `AGENTS.md` だけを頼りに、次の3つに答えられるか自分で試す。

- この repo のテストはどう回すか
- 新しい機能のコードをどこに置くか
- 触ってはいけないものは何か

**完了条件**: 3つとも答えられる。答えられないものがあれば §1 に戻って材料を足す。
